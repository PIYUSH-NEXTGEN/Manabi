## A. Overall assessment

The practice standards are already well above typical hackathon-grade code: tests are meaningful and mostly behavior-level, the seed/pagination/status machinery is regression-tested, and recent refactors left the codebase consistent. Phase 3 was therefore mostly an exercise in *drift removal*: features removed in earlier commits (FeaturedProblems, heatmap, open-call section) had left usable-but-dead code behind, and a few helpers had grown duplicated across routers/scripts. All of that is now consolidated. Net: **-903 lines, +353 lines** across both commits.

## B. Bugs found and fixed during review

- **F-1 (high, fixed + regression-tested):** `create_problem` wrote `body.datasets` (the Pydantic list object) into `Problem.datasets` (a `JSON` column) without materializing it; under some drivers this serializes an unjsonable wrapper and 500s problem creation with datasets. Fixed in `backend/app/routers/problems.py` (`datasets=list(body.datasets)`) with regression test `test_problem_create_stores_datasets` (`backend/tests/test_wiring.py`). This was the only correctness bug found; everything else in Phase 3 was cleanup.

## D. Duplication consolidated

- **F-2 (backend):** row→schema presenters (`problem_to_out`, `project_to_out`, `project_out_safely`) extracted into `backend/app/services/presenters.py`; previously each router re-derived the same privacy-redaction logic.
- **F-4 (backend):** repo-URL/ownership logic unified: `verification.ownership_from_repo` and new `repo_was_renamed_or_transferred` are now the single source of truth used by both the live refresh path and `scripts/reverify_projects.py` (which deleted its private `_ownership_from_facts` copy); `github._fetch_commits` → public `fetch_commits` shared by both callers.
- **F-5 (backend):** implementation details moved behind names/named settings: `auth.me` uses `visibility.is_admin(user)` (no local admin predicate), `REPORT_LIMITER` uses a new `REPORT_RATE_LIMIT_PER_HOUR` config setting (documented in `.env.example`/`DEPLOY.md`), timezone handling unified behind `models.as_utc` (replaced `_aware` copies in `projects.py`, `recommendations.py`, `verification.py`), and the dead `Authorization`-based re-verify clause in `get_project_progress` was simplified to `user is not None` (token auth has been gone for a while).
- **F-6 (frontend):** `frontend/src/lib/repoUrl.ts` now owns `GITHUB_REPO_URL_PATTERN` + `stripGitSuffix`, used by `SubmitProjectPanel`, `RepoAnalyzerPage`, and the msw `handlers.ts` (three previously divergent copies of the same regex — the mock now actually enforces what the panel enforces).
- **F-7 (frontend):** `frontend/src/lib/limits.ts` owns `SOLUTION_SUMMARY_MAX = 400`, consumed by `DashboardPage`, `SubmitProjectPanel` (including its `maxLength`/counter/placeholder) and the msw handler — previously "400" appeared as three literals; in the msw mock it was copy-paste, in the panel it is now impossible to drift from the textarea cap.
- **F-11 (frontend):** the two `Progress.status` presentation maps consolidated into `frontend/src/design/status.ts` (`PROGRESS_STAMPS`, used by `ProjectProgressBadge` and home `BuildInPublic`). Deliberately *not* merged: `STATUS_TAGS`/`statusLabel` (DashboardPage / ProjectDetailPage) — their labels are different, already-covered copy, respectively.

## E. Robustness / type-safety improvements

- **TS-3:** `checkCompletionError` (`DashboardPage.tsx`) no longer trusts a bare `as CompletionChecklistItem[]` cast on mock/server-provided 422 payload; it now validates each checklist entry shape and drops malformed items.
- **TS-4:** `ProblemBoardPage.goalOf` is now `(problem: ProblemOut)` instead of `any`, and the board's goal filter derives from the existing `GOAL_OPTIONS` constant instead of a hand-built literal — the filter can no longer be typed with a goal missing from the options.
- **TS-5:** `RepoAnalyzerPage` had a dead trailing `setError(undefined)` (unreachable "valid" state) — removed; the page now uses the shared `GITHUB_REPO_URL_PATTERN`, so panel and analyzer can't disagree about the URL shape.

The remaining TS dead zone is the one large prerequisite noted in G: generating `schema.ts` from OpenAPI (via `openapi-typescript`) would turn `ProblemOut['verification_status']`-style lookups into GraphQL-grade exhaustiveness and remove the hand-maintained `components` block in `frontend/src/api/schema.ts`.

## F. Not adopted (with reasons)

- **L-1 ESLint:** a new dependency + baseline pass (native type-checking/lint warnings would be valuable as follow-up, but adding a linter now exceeds this pass's risk budget; recorded as next phase candidate).

- **L-3 vitest 3→5 / react-router 6→7:** major-version migrations, out of scope for a behavior-preserving pass.
- **L-4 moderation flow / CSP:** policy-level rather than refactoring; not addressed.

## Handover notes for a new engineer

- Everything regression-critical lives in `backend/tests/test_wiring.py` (wiring, seeding idempotence, rate limits, datasets), `backend/tests/test_verification*`, and the vitest behavior suites (`*.test.tsx`).
- Data invariant: re-running any `seed` module is idempotent (runner de-dupes by slug); `seed_problems()` owns that from now on.
- If you change `solution_summary` limits in `backend/app/schemas.py`, change them once in `frontend/src/lib/limits.ts` — that file's existence is what keeps 400-caps aligned across form, counter, placeholder, and mock.
- Frontend errors/skeletons for detail pages are shared via `frontend/src/pages/detailStates.tsx`; new detail-style pages should reuse `PageSkeleton`/`LoadErrorPanel` instead of re-inline them.
- Repo-URL validation must go through `frontend/src/lib/repoUrl.ts` (pattern + suffix stripping) — three ad-hoc copies were the source of the 422 drift fixed here.
