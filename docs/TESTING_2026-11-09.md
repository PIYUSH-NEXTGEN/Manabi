## B. Test quality assessment

What the suite does well (keep): per-file engine isolation, honest user-visible outcomes over CSS selectors, MSW unhandled-request=error, dependency-overrides cleared in teardowns, no snapshot tests.

Defects found and fixed this phase:

| ID | Location | Defect | Fix |
|---|---|---|---|
| TQ-1 | `tests\test_github_heatmap.py` `_iso`/recent_day | Midnight-UTC race: event timestamps and the expected bucket date were derived from **two separate `datetime.now()` calls**; when the clock flipped between them the count landed on the wrong day (the same class of flake as the suite's earlier 1.3s vitest flake, different layer) | Freeze a single `now` for both the events and the expected date |
| TQ-2 | `tests\test_models.py` (3 tests) | `except Exception: raised = True; assert raised` — asserts *that* something raised, not the contract (IntegrityError); a 500 from a broken fixture would still pass | `pytest.raises(IntegrityError)` in all three uniqueness tests |
| TQ-3 | `tests\test_curated_projects.py`, `test_curated_intermediate_projects.py` | `_client()` helper registered `get_db` overrides and **never cleared them or closed the session** — cross-file leakage vector | Converted to a yield-fixture that clears overrides + closes session |
| TQ-4 | `tests\test_llm.py` | `pytest.raises((LLMResponseError, LLMConfigError))` — could mask a config-vs-response misclassification | Narrowed to `pytest.raises(LLMResponseError)` (verified: anthropic 500 does map to `LLMResponseError`) |
| TQ-5 | `tests\test_models.py`, others | Pre-existing unused locals (`pyflakes` warnings) | Removed; `pyflakes tests` is now clean |
| TQ-6 | `frontend\src\api\mocks\handlers.ts` | `changeSubmissionStatus` only flipped a status flag in place — approve did **not** move a row between queues, and module-level admin state never reset between tests | Rows now move queues (GET reflects actions) + exported `resetMockHandlersState()` restored in `afterEach` via `setup.ts` |
| TQ-7 | `frontend\e2e\smoke.spec.ts` | **Test rot proved**: the smoke run failed twice against the real app — it asserted a hero H1 `MANABI` and a nav link `Problems` that no longer exist (hero is `Pick a project. Ship it. Prove it.`, nav+board are `Projects`). Because CI never runs e2e, this rotted silently | Updated to current UI copy; e2e now green. This is direct evidence for F-1 |

Flakiness observed & fixed: the App route-table tests (`/` home render, lazy chunks + motion) failed once under full parallel load (`Test timeout 5s`, whole-file wall 17.8 s). ## F. Remaining gaps / recommendations (honest)

1. **Add the frontend suites + e2e to CI.** The stale-smoke rot (TQ-7) is the concrete proof: vitest and Playwright run nowhere in `.github\workflows\ci.yml`, so UI assertions rot until someone runs them locally. Minimum viable: `npm run test` in the frontend job; Playwright can follow with `npx playwright install --with-deps chromium` and an artifacts-on-failure upload.
2. **No frontend coverage tooling** — vitest has no `--coverage` provider configured; a `@vitest/coverage-v8` devDep is the cheapest measurable step if coverage gates are wanted. Not added in this phase to avoid pampering the dependency manifest beyond the audit need.
3. **Backend coverage is global 85% but unevenly gated** — `app\services\verification.py` (76%) and `github.py` (76%) hide the largest miss counts; if a threshold gate is desired, start per-file rather than global.
4. **Rate-limit tests still poke private `_hits` buckets** (and clear them). A tiny `reset()` method on `RateLimiter` would remove the encapsulation poke and the cross-test order dependency for good.
5. **`no conftest.py` duplicates ~20 lines of engine/client fixtures per file.** A shared conftest would cut ~200 lines, but per-file isolation was deliberately valued during phases 1–4; revisit only when a third suite (e.g. API contract tests) makes the duplication painful.
6. Only one e2e journey exists (home → board → detail). Board-filter and submit journeys would be next value; the MSW state mutation added this phase makes later flow journeys feasible.

## G. Final assessment

**Grade: B+.** The suite is now healthy, honest, and deterministic on the paths the product can't afford to regress: the phase-1–4 fixes each have a named regression test, both API surfaces answer their full failure-mode matrices (auth/404/409/422/429/502/503) at least once, frontend error-code mapping is end-to-end asserted per case, and every flake or leak found in this phase was eliminated rather than skipped (verified: 2 clean full backend runs including coverage, 3 clean consecutive frontend runs, green e2e, green tsc/build, clean pyflakes). What keeps it from an A is structural, not behavioral: CI does not execute the frontend/e2e suites (rot is now proven, fix is a small workflow edit), and there is no coverage gate on either stack — both are one-session follow-ups listed in F.
